## Release A — do this now

The parity sprints are closed. Tosin is moving accounts and the wallet. Your job is to keep the runtime honest while he does that.

1. Make the gate match section 2 and the interface list in the contracts file. The functions are `entitled()`, `editionStatus()`, `createWorkspaceAccess()`, and `hostedWorkspaceConfiguration()` in `server/enterprise.ts`. An entitlement id that is not in the frozen set grants nothing. A missing or expired license degrades to the free edition. Do not copy the deleted upstream `enterprise/` tree.

2. Make the five provider ids honor all three switches: operator kill-switch, workspace admin toggle, per-bot model choice. The ids are exactly `claude`, `codex`, `grok`, `kimi`, `muse`. An unknown id grants nothing and stays hidden. An off provider is hidden with a reason. The code is `server/switchboard.ts` and the drivers under `server/drivers/`.

3. Prove the key split. A bring-your-own turn uses the person's key and never the gateway key. A bundled turn uses the gateway key and never the person's key. Assert both directions in a test. The gateway file is Tosin's. If the proof requires an edit there, hand him the failing test and the sentence it must satisfy. Do not edit `server/billing/gateway.ts` yourself in Release A.

4. Mount route modules when they arrive. Read the module. If it reaches into bots, browsers, or turns, send it back. Billing stays in Tosin's routes. Client-only work never needs a mount from you.

Run the harness tests you touch, then `pnpm typecheck` on the server project. The full `pnpm test` is the release-gate command. Run it before you ask for acceptance, on a fixture, not on your own `~/.maximus`.

### Report Release A like this

Name the proof, the command, and the result. Example: "`server/switchboard.test.ts` — 5 providers × 3 levels, off providers hidden with a reason. `pnpm exec vitest run server/switchboard.test.ts server/enterprise.test.ts` passed." "Gate looks good" is not a report.

### Release A is done when

The gate tests and the provider matrix pass, the key-split test passes in both directions, and a packaged server from Lanre's installer completes one turn on each provider the switchboard has turned on.

## Release B — wait for the tag

Start these only after the product manager opens them. The proofs are in [2026-11-10-grok-parity-roadmap.md](2026-11-10-grok-parity-roadmap.md). Build on the files named there. Do not add Firecracker, Redis, LiteLLM, a second browser, or a second secret store.

**Sprint 1.** Persist the per-bot wait queue and the in-flight turn id under the data directory. A restart either resumes the turn or marks it interrupted with the transcript still there. New bots default to `perBotLocalVmTarget` in `server/container-computer.ts` and to their own browser profile. Shared computer stays available as a setting. Call Tosin's awake-hold debit. Do not edit the wallet yourself. Lanre reattaches the clients to the stream you persist.

Proof: start a turn on an isolated harness, stop the client, restart the server, open the client, and read the same turn. A second bot's container is `perBotLocalVmTarget`, and its browser profile id is its own.

**Sprint 2.** Add a room handoff: from bot, to bot, task id, payload, and the thread it lands in. The receiver wakes on its own lane, the way group goals already wait in `server/group-goal-run.ts`. CAPTCHA, 2FA, checkout, and outbound email pause browser tools and push the existing `approval` kind. A new bot's file root is its own. A group workspace is a setting someone turns on.

Proof: Bot A's memory file does not contain Bot B's payload. A fixture page marked checkout opens an approval and does not submit.

**Sprint 3.** Wait until Tosin's per-bot ceiling has merged. Then, in `server/billing/gateway.ts`, classify a bundled call as format or reason. Format uses the cheap model pinned in the ration profile. Reason uses the bot's selected model. Bring-your-own calls skip the router and keep the person's key. One pull request, after his. Also add an external runner manifest beside `server/webhooks.ts`: name, URL, auth, input schema, which bots may call it. Calling that URL is a side effect and uses the approval card. The inbound webhook still starts our bot.

Proof: a format call hits the cheap model id, a reason call hits the selected id, and a replayed webhook still runs once.

**Sprint 4.** Record browser actions with the verbs the agent already calls. Steps are selectors and labels, never pixels. A finished recording becomes a skill with named parameters, reviewed through the existing skill-review flow, runnable by any bot on the account that is granted it. A step that needed approval on the way in still needs it on replay. Then add a read-only semantic cache in front of model calls whose tool trace is entirely reads. A POST, a click, a send, or a payment never hits it. A hit writes a zero-debit ledger row through Tosin's ledger API. You do not write the skill store checkout. That is his, and it waits until a stranger can run your skill.

Proof: one model call authors the skill, and a replay with one parameter changed makes none. A POST in the trace misses the cache.
