# Lanre — instructions

You own what a person installs and taps. The product manager accepts your work only when the proof at the bottom of each section passes on a clean machine, not on your daily Maximus data.

Read [2026-11-10-team-execution-roadmap.md](2026-11-10-team-execution-roadmap.md) for how the three of you stay apart. Your spec for this release is [2026-11-06-maximus-takeover-roadmap.md](2026-11-06-maximus-takeover-roadmap.md), Track 1. The phone spec is [2026-11-08-flutter-mobile-roadmap.md](2026-11-08-flutter-mobile-roadmap.md). Phases 0–10 of that phone plan are already built. Do not rebuild them.

## Your directories

You edit only:

- `electron/`
- `src/`
- `mobile/`
- `build/`
- the desktop and mobile release workflows under `.github/workflows/`

You do not edit `server/`. If a screen needs a new HTTP route, write the client against the route Wande or Tosin already shipped. If the route does not exist, ask the product manager. Wande mounts routes. You do not open `server/index.ts`.

You do not enroll Apple, Google, or Windows certificate accounts. Those stay with the owner. You prepare the build so the owner can sign and upload.

## Release A — do this now

The parity sprints are closed. Ignore them until the product manager says the v0.1.0 tag passed.

1. Search your trees for the old name.

   ```bash
   rg -li 'openmausbot|mausbot' electron src mobile
   ```

   Hits are allowed only in attribution and in the one-time move from `~/.openmausbot` to `~/.maximus`. Everything else becomes Maximus. The frozen name list is section 1 of [2026-11-06-maximus-contracts.md](2026-11-06-maximus-contracts.md).

2. Produce the three installers from the pipeline, not from a one-off on your laptop.

   - macOS arm64 and x64: `pnpm package:mac`. The release artifact is signed and notarized. A dev-signed dmg is a local check, not the tag.
   - Windows x64: the release artifact comes from `.github/workflows/package-win.yml`. `pnpm package:win` on a Mac is a check. The installer that ships is the OV-signed one from CI.
   - Linux x64: `.github/workflows/package-linux.yml` on real x64. An emulated container is not the proof. The CUA archive hash in the package must match the pin.

3. On each installer, install, launch, and finish one agent turn. The update feed (`latest-mac.yml`, `latest.yml`, `latest-linux.yml`) must match the files you just built.

4. Phone: from `mobile/`, keep `flutter analyze` and `flutter test` green. Leave the store listing in `mobile/STORE_RELEASE.md`. Do not submit to TestFlight or Play.

Leave the admin dashboard, the sign-in endpoint picker, and the phone feature phases as they are.

### Report Release A like this

Name the proof, the command, and the result. Example: "`package-linux.yml` run 1234 produced `Maximus-*-amd64.deb`. Installed on Ubuntu 24.04 x64. One turn completed. CUA hash matched." "Packaging is in progress" is not a report.

### Release A is done when

All three installers from one pipeline install, boot, and finish a turn, and the rebrand search on `electron/`, `src/`, and `mobile/` is clean outside the exceptions above.

## Release B — wait for the tag

Start these only after the product manager opens them. The behavior is in [2026-11-10-grok-parity-roadmap.md](2026-11-10-grok-parity-roadmap.md). You build the clients. Wande builds the runtime those clients attach to.

**Sprint 1.** Desktop, phone, and the browser reattach to a turn that is already running. Show the events that happened while the client was closed. Wande persists the queue. You consume that stream. Do not invent a second event channel.

**Sprint 2.** Render the approval card Wande pauses on, including a checkout pause, on desktop and on the phone. The card already exists. A checkout is another reason it opens.

**Sprint 3.** No server work. A settings screen for the per-bot ceiling waits until Tosin's API is frozen and the product manager names the screen. Do not design it early.

**Sprint 4.** Package the headless server as a daemon for macOS, Windows, and Linux. The Electron app and the phone are clients of that daemon. The recorder review screen uses Wande's existing skill-review flow. You package and present it. You do not write the recorder.

### Release B is done when

Sprint 1: a client closed mid-turn reopens on the same turn and shows the earlier events. Sprint 4: the daemon answers `GET /api/health` with the app window closed, on each OS you package.
